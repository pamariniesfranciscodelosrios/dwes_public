    1. Investigación, instalación y primera ejecución de Laravel

    En esta actividad

    • instalarás y configurarás un entorno de desarrollo para Laravel,
    • crearás tu primer proyecto y
    • documentarás todo el proceso mediante evidencias.

    El objetivo no es únicamente conseguir que Laravel funcione. También deberás investigar qué herramientas intervienen, comprender para qué sirve cada una, registrar los problemas encontrados y explicar cómo los has solucionado.

    2. Resultado de aprendizaje relacionado

    RA 8: Genera páginas web dinámicas analizando y utilizando tecnologías y frameworks del servidor web que añadan código al lenguaje de marcas.

    Con esta actividad se trabajan especialmente las siguientes capacidades:

    • Identificar Laravel como framework de desarrollo web del lado del servidor.
    • Reconocer las ventajas de utilizar un framework frente a PHP procedimental.
    • Preparar correctamente un entorno de desarrollo.
    • Crear y ejecutar una aplicación Laravel.
    • Utilizar herramientas profesionales como Composer, Artisan, Node.js, NPM y Git.
    • Documentar de forma técnica un proceso de instalación y resolución de problemas.

    3. Organización del repositorio

    El trabajo debe almacenarse en la siguiente ruta:

    DWES_Nombre_Alumno/
└── UD6/
    └── S1/

    4. Desarrollo de la actividad

    4.1. Parte A. Conceptos básicos

    1. ¿Qué es Laravel?
    2. ¿Qué es un framework?
    3. ¿Qué diferencias encuentras entre trabajar con PHP procedimental y utilizar Laravel?
    4. ¿Qué ventajas proporciona Laravel en proyectos medianos o grandes?
    5. ¿Qué significa que Laravel utiliza el patrón MVC?

    Selecciona tres herramientas del ecosistema Laravel e investiga para qué sirven.

    Puedes elegir entre:

    • Sanctum.
    • Passport.
    • Cashier.
    • Horizon.
    • Scout.
    • Socialite.
    • Telescope.

    Para cada herramienta indica:

    • Su función principal.
    • En qué tipo de aplicación podría utilizarse.
    • Un ejemplo concreto de uso.

    No se valorará la copia literal de páginas web. Se valorará la capacidad de resumir, comparar y extraer conclusiones propias.

    4.2. Parte B. Comprobación del entorno

    Antes de instalar Laravel, comprueba las herramientas disponibles en tu equipo.

    Ejecuta los siguientes comandos:

    php -v
composer -V
node -v
npm -v
git --version

    Añade capturas donde se vean claramente los comandos y sus resultados.

    Ejemplo:

    ## Comprobación del entorno

- Sistema operativo: Windows 11
- Entorno utilizado: Laragon
- PHP: 8.3.x
- Composer: 2.x
- Node.js: 20.x
- NPM: 10.x
- Git: 2.x

    4.3. Parte C. Instalación de Laravel

    Puedes crear el proyecto utilizando uno de los siguientes métodos.

    Método 1. Composer

    composer create-project laravel/laravel primera-app "^12.0"

    Método 2. Instalador global de Laravel

    composer global require laravel/installer
laravel new primera-app

    Documenta

    1. El método utilizado.
    2. La carpeta desde la que ejecutaste el comando.
    3. El comando completo.
    4. Los mensajes relevantes mostrados en la terminal.

    5. Las decisiones tomadas por el instalador interactivo, cuando corresponda:

    6. Starter kit.

    7. Framework de pruebas.
    8. Base de datos.
    9. Inicialización de Git.

    Incluye capturas del proceso de creación y ejecución del proyecto.

    4.4. Parte D. Verificación de la instalación

    Entra en la carpeta del proyecto:

    cd primera-app

    Comprueba la versión instalada:

    php artisan --version

    Lista algunos de los comandos disponibles:

    php artisan list

    Inicia el servidor:

    php artisan serve

    Accede desde el navegador a:

    http://127.0.0.1:8000

    o:

    http://localhost:8000

    Debes aportar las siguientes evidencias:

    • Captura de php artisan --version.
    • Captura del servidor iniciado.
    • Captura de la página inicial de Laravel en el navegador.
    • En la captura del navegador debe apreciarse la dirección utilizada.

    4.5. Parte E. Instalación y ejecución de Vite

    Dentro del proyecto ejecuta:

    npm install
npm run dev

    Explica brevemente:

    • Qué descarga npm install.
    • Para qué sirve npm run dev.
    • Qué relación tiene Vite con los archivos CSS y JavaScript.

    • Por qué normalmente deben mantenerse abiertos dos procesos:

    • El servidor PHP de Laravel.

    • El servidor de desarrollo de Vite.

    Incluye una captura en la que se vea Vite ejecutándose correctamente.

    4.6. Parte F. Exploración inicial del proyecto

    Localiza y explica brevemente la función de los siguientes elementos:

    app/
config/
database/
public/
resources/
routes/
storage/
tests/
.env
artisan
composer.json
package.json

    No es necesario describir todos los archivos internos.

    Incluye una captura del árbol de directorios del proyecto desde el editor o desde la terminal.

    Puedes obtenerlo con comandos como:

    tree

    En Windows también puedes utilizar:

    tree /F

    La captura debe evitar mostrar completamente las carpetas vendor y node_modules, ya que contienen miles de archivos.

    5. Registro de problemas

    Documenta los errores, dudas o dificultades que hayas encontrado.

    Para cada problema utiliza la siguiente estructura:

    Campo Información que debes aportar
    Síntoma Mensaje exacto y acción que lo provoca.
    Diagnóstico Qué comprobaste y qué causa identificaste.
    Solución Pasos y comandos aplicados.
    Verificación Evidencia de que funciona después del cambio.

    Si no aparecen errores, documenta una comprobación preventiva real; no inventes incidencias.

    6. Publicación en GitHub

    Desde el repositorio del módulo, realiza los commits necesarios. Si usas el repositorio compartido del módulo, evita crear un segundo repositorio Git dentro de UD6/S1. Revisa el .gitignore antes de añadir archivos: excluye .env, vendor/, node_modules/, logs y bases de datos locales con información privada; conserva .env.example sin secretos y los archivos lock.

    Ejemplo orientativo:

    git add UD6/S1
git commit -m "Añade actividad de introducción e instalación de Laravel"
git push

    Se recomienda realizar varios commits durante el proceso:

    Añade investigación inicial sobre Laravel
Documenta comprobación del entorno
Añade instalación y primera ejecución
Documenta problemas encontrados
Completa evidencias de la sesión 1

    Antes de entregar, comprueba que:

    • La ruta es exactamente DWES_Nombre_Alumno/UD6/S1.
    • Los archivos Markdown se visualizan correctamente.
    • Todas las imágenes aparecen en GitHub.
    • Los enlaces relativos funcionan.
    • No se ha subido la carpeta vendor.
    • No se ha subido la carpeta node_modules.
    • No se han publicado contraseñas ni datos sensibles.
    • El repositorio está actualizado con git push.

    UD6/S1

    Windows con Laragon
Windows con XAMPP
macOS con Herd
macOS con Homebrew
Linux con instalación manual

    8. Ampliación voluntaria

    El alumnado que finalice la actividad puede realizar una o varias ampliaciones:

    • Crear el proyecto utilizando un segundo método de instalación.
    • Ejecutar Laravel en un puerto diferente:
    php artisan serve --port=8080
    • Investigar el contenido del archivo .env, sin publicar contraseñas.
    • Cambiar el nombre de la aplicación mediante APP_NAME.
    • Ejecutar:
    php artisan route:list
    • Localizar la ruta responsable de mostrar la página inicial.
    • Modificar de forma sencilla la vista inicial.
    • Investigar la diferencia entre entorno de desarrollo y producción.
    • Comparar Laragon, XAMPP y Laravel Herd.

    Las ampliaciones deben quedar documentadas mediante texto, comandos y capturas.
