    Toda la explicación de la práctica debe incluirse en un único archivo llamado sesion2.md.

    1. Objetivo

    Explorar la estructura de un proyecto Laravel, modificar algunas variables del archivo .env y utilizar Artisan para generar los primeros componentes de una aplicación.

    Utiliza el proyecto Laravel creado en la sesión anterior.

    2. Exploración de la estructura

    Abre el proyecto Laravel en Visual Studio Code y localiza las siguientes carpetas y archivos:

    app/
config/
database/
public/
resources/
routes/
storage/
tests/
vendor/
.env
.env.example
artisan
composer.json
package.json
vite.config.js

    En sesion2.md, explica con una frase la función de cada elemento.

    3. Configuración del archivo .env

    Modifica temporalmente las siguientes variables:

    APP_NAME="Proyecto Sesion 2"
APP_ENV=local
APP_DEBUG=true
APP_URL=http://localhost:8000
APP_TIMEZONE=Europe/Madrid
APP_LOCALE=es
APP_FALLBACK_LOCALE=es

    Recuerda en proyectos reales, no se debería mostrar la clave completa de APP_KEY ni contraseñas.

    Después, ejecuta:

    php artisan config:clear

    En sesion2.md, explica brevemente:

    1. Para qué sirve el archivo .env.
    2. Qué diferencia existe entre .env y .env.example.
    3. Por qué .env no debe subirse a Git.
    4. Por qué APP_DEBUG debe estar en false en producción.

    4. Lectura de la configuración

    Añade temporalmente al archivo routes/web.php la siguiente ruta:

    use Illuminate\Support\Facades\Route;

Route::get('/configuracion', function () {
    return [
        'nombre' => config('app.name'),
        'entorno' => config('app.env'),
        'debug' => config('app.debug'),
        'zona_horaria' => config('app.timezone'),
        'idioma' => config('app.locale'),
    ];
});

    Ejecuta el servidor:

    php artisan serve

    Accede a:

    http://localhost:8000/configuracion

    Incluye una captura del resultado y explica por qué es preferible utilizar:

    config('app.name');

    en lugar de acceder directamente mediante:

    env('APP_NAME');

    7. Ejemplo2. Modelo Eloquent

    Añade una captura del modelo.

    8. Ejemplo 3. Modelo con migración

    Ejecuta:

    php artisan make:model Category -m

    Comprueba que Laravel ha generado:

    app/Models/Category.php
database/migrations/...create_categories_table.php

    Añade una captura donde se vean ambos archivos.

    9. Ejemplo 4. Migración de artículos

    Ejecuta:

    php artisan make:migration create_articles_table

    Localiza el archivo generado dentro de:

    database/migrations/

    Modifica su método up() para que contenga:

    public function up(): void
{
    Schema::create('articles', function (Blueprint $table) {
        $table->id();
        $table->string('title');
        $table->text('body');
        $table->timestamps();
    });
}

    No es necesario ejecutar todavía la migración.

    10. Ejemplo 5. Form Request

    Ejecuta:

    php artisan make:request StoreArticleRequest

    Modifica el método rules():

    public function rules(): array
{
    return [
        'title' => 'required|max:255',
        'body' => 'required|min:100',
    ];
}

    Archivo generado:

    app/Http/Requests/StoreArticleRequest.php

    11. Ejemplo 6. Ruta básica

    Añade en routes/web.php:
