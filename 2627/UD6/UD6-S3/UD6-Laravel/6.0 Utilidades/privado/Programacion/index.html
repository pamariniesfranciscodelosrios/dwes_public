    Referencias

    Esta unidad está basada en el curso Laravel en Español que puedes encontrar aquí

    www.laraveles.es

    Eso si, durante el desarrollo de las clases vamos a realizar modificaciones.

    El motivo por el que cambio a este curso son:

    Distribución de contenidos de Laravel en 10 sesiones

    Duración total: 20 horas Duración por sesión: 2 horas Criterio: Cada sesión continúa el desarrollo de un pequeño gestor de productos o artículos, que terminará convirtiéndose en un CRUD protegido mediante autenticación.

    Sesión 1. Introducción e instalación de Laravel

    Archivos

    1. Qué es Laravel
    2. Instalación

    Distribución temporal

    Tiempo Contenido
    0–25 min Qué es un framework y qué problemas resuelve Laravel
    25–45 min Arquitectura MVC y componentes principales de Laravel
    45–65 min Requisitos: PHP, Composer, Node.js y base de datos
    65–100 min Instalación y creación del primer proyecto
    100–115 min Ejecución del servidor y comprobación del entorno
    115–120 min Registro de evidencias y conclusiones

    Contenidos principales

    • Concepto de framework.
    • Características de Laravel.
    • Patrón Modelo-Vista-Controlador.
    • Eloquent, Blade, Artisan y migraciones.
    • Requisitos del entorno.
    • Creación de un proyecto mediante Composer.
    • Servidor de desarrollo.
    • Instalación de dependencias de frontend.

    Práctica

    composer create-project laravel/laravel gestor-productos
cd gestor-productos

php artisan serve

npm install
npm run dev

    Evidencia

    • Proyecto Laravel funcionando.
    • Captura de la página inicial.
    • Resultado de:
    php -v
composer -V
node -v
php artisan --version

    Laravel se presenta como un framework MVC que incorpora, entre otras herramientas, Eloquent, Blade, migraciones y Artisan. La instalación requiere preparar PHP, Composer y, para los recursos de frontend, Node.js.

    Sesión 3. Primera ruta e introducción a Blade

    Archivos

    1. Tu primera ruta y respuesta
    2. Introducción a las vistas en Laravel
    3. Blade: el motor de plantillas

    Distribución temporal

    Tiempo Contenido
    0–30 min Concepto de ruta y verbos HTTP
    30–50 min Tipos de respuesta
    50–70 min Creación y organización de vistas
    70–95 min Sintaxis básica de Blade
    95–115 min Práctica de rutas y vistas
    115–120 min Revisión

    Contenidos principales

    • Archivos routes/web.php y routes/api.php.
    • Rutas GET y parámetros.
    • Respuestas de texto, arrays, JSON, vistas y redirecciones.
    • Carpeta resources/views.
    • Archivos .blade.php.
    • Notación de punto para localizar vistas.
    • Impresión segura con {{ }}.
    • Condicionales y bucles.
    • Directiva @forelse.
    • Variable $loop.
    • Diferencia entre {{ }} y {!! !!}.

    Práctica

    Crear las rutas:

    Route::get('/', function () {
    return view('inicio');
})->name('inicio');

Route::get('/productos', function () {
    $productos = [
        ['id' => 1, 'nombre' => 'Portátil', 'precio' => 850],
        ['id' => 2, 'nombre' => 'Monitor', 'precio' => 220],
        ['id' => 3, 'nombre' => 'Teclado', 'precio' => 65],
    ];

    return view('productos.index', compact('productos'));
})->name('productos.index');

Route::get('/productos/{id}', function (int $id) {
    return view('productos.show', compact('id'));
})->whereNumber('id')->name('productos.show');

    Crear:

    resources/views/inicio.blade.php
resources/views/productos/index.blade.php
resources/views/productos/show.blade.php

    Evidencia

    Una página inicial, un listado de productos y una página que reciba un parámetro de ruta.

    Las rutas pueden devolver texto, JSON, vistas o redirecciones, además de utilizar parámetros obligatorios, opcionales y restringidos. Las vistas se almacenan en resources/views y se referencian mediante notación de punto. Blade compila sus plantillas a PHP y escapa automáticamente la salida mostrada mediante {{ }}.

    • @extends, @section, @yield y @parent.

    • Componentes Blade y $slot.
    • Paso de datos con arrays.
    • Uso de compact().

    • Directivas:

    • @if, @unless, @switch.

    • @isset y @empty.
    • @auth y @guest.
    • @csrf y @method.
    • @error.
    • @checked, @selected, @disabled.
    • @includeWhen y @includeIf.

    Práctica

    Crear la estructura:

    resources/views/
├── layouts/
│   └── app.blade.php
├── components/
│   ├── alert.blade.php
│   └── producto-card.blade.php
└── productos/
    ├── index.blade.php
    └── show.blade.php

    Utilizar:

    @extends('layouts.app')

@section('titulo', 'Productos')

@section('contenido')
    @forelse ($productos as $producto)
        <x-producto-card :producto="$producto" />
    @empty
        <x-alert>No existen productos.</x-alert>
    @endforelse
@endsection

    Evidencia

    Aplicación con un layout común, navegación, componente reutilizable y listado dinámico.

    Sesión 5. Configuración de la base de datos y migraciones

    Archivos

    1. Configurar BBDD

    Distribución temporal

    Tiempo Contenido

    25–45 min Configuración en.env
    45–65 min Introducción a las migraciones
    65–95 min Columnas, restricciones e índices

    Contenidos principales

    • Configuración de SQLite o MySQL.
    • Variables DB_CONNECTION, DB_HOST, DB_PORT, DB_DATABASE, DB_USERNAME y DB_PASSWORD.
    • Métodos up() y down().
    • Tipos de columnas.
    • Valores predeterminados y columnas nullable.
    • Índices.
    • Claves foráneas.
    • Ejecución, estado y reversión de migraciones.

    Práctica

    Crear las tablas:

    • categorias
    • productos
    php artisan make:migration create_categorias_table
php artisan make:migration create_productos_table

    Ejemplo de relación:

    Schema::create('productos', function (Blueprint $table) {
    $table->id();
    $table->foreignId('categoria_id')
        ->constrained()
        ->cascadeOnDelete();

    $table->string('nombre');
    $table->text('descripcion')->nullable();
    $table->decimal('precio', 8, 2);
    $table->integer('stock')->default(0);
    $table->boolean('activo')->default(true);
    $table->timestamps();
});

    Comprobar:

    php artisan migrate
php artisan migrate:status
php artisan migrate:rollback
php artisan migrate

    Evidencia

    Migraciones funcionales y reversibles para categorías y productos.

    Las migraciones versionan la estructura de la base de datos mediante los métodos up() y down(), y permiten aplicar o revertir cambios de forma reproducible.

    Sesión 7. Relaciones y comparación entre Eloquent y Query Builder

    Archivos

    1. Relaciones
    2. Query Builder vs Eloquent

    Distribución temporal

    Tiempo Contenido
    0–35 min Relaciones uno a uno y uno a muchos
    35–60 min Relaciones muchos a muchos
    60–80 min Eager loading y problema N+1
    80–100 min Introducción al Query Builder
    100–115 min Comparación práctica
    115–120 min Conclusiones

    Contenidos principales

    • hasOne.
    • hasMany.
    • belongsTo.
    • belongsToMany.
    • Tablas pivot.
    • attach(), detach() y sync().
    • Carga anticipada con with().
    • Conteo con withCount().
    • Problema N+1.
    • Consultas con DB::table().

    • Diferencias entre:

    • Objetos Eloquent.

    • Objetos stdClass.
    • Relaciones y eventos.
    • Consultas masivas y analíticas.

    Práctica

    Definir:

    // Categoria.php
public function productos()
{
    return $this->hasMany(Producto::class);
}

// Producto.php
public function categoria()
{
    return $this->belongsTo(Categoria::class);
}

    Realizar dos consultas equivalentes:

    $productos = Producto::with('categoria')
    ->where('activo', true)
    ->orderBy('precio')
    ->get();

    $productos = DB::table('productos')
    ->join('categorias', 'categorias.id', '=', 'productos.categoria_id')
    ->select('productos.*', 'categorias.nombre as categoria')
    ->where('productos.activo', true)
    ->orderBy('productos.precio')
    ->get();

    Evidencia

    Comparativa razonada entre ambas soluciones e identificación del problema N+1.

    Sesión 8. Controladores y Resource Controllers

    Archivos

    1. Controladores
    2. Resource Controllers

    Distribución temporal

    Tiempo Contenido
    0–30 min Función de los controladores en MVC
    30–50 min Creación y conexión con rutas
    50–75 min Métodos convencionales de un CRUD
    75–95 min Resource Controllers
    95–115 min Route Model Binding
    115–120 min Revisión

    Contenidos principales

    • Creación de controladores.
    • Inyección del objeto Request.
    • Controladores invocables.
    • Controladores delgados.

    • Métodos REST:

    • index

    • create
    • store
    • show
    • edit
    • update
    • destroy
    • Route::resource().
    • Route Model Binding.
    • Redirecciones y mensajes flash.
    • Method spoofing.

    Práctica

    Crear:

    php artisan make:controller ProductoController --resource

    Registrar:

    Route::resource('productos', ProductoController::class);

    Comprobar:

    php artisan route:list --name=productos

    Implementar inicialmente:

    • index()
    • show()
    • create()
    • edit()

    Los controladores separan la lógica de las rutas y actúan como intermediarios entre modelos y vistas. Un Resource Controller proporciona las siete acciones convencionales necesarias para un CRUD web.

    Evidencia

    Listado, detalle y formularios conectados mediante un Resource Controller.

    Tiempo Contenido

    Contenidos principales

    • Parámetros obligatorios y opcionales.
    • Restricciones whereNumber() y whereAlphaNumeric().
    • Rutas con nombre.
    • Grupos de rutas.
    • Prefijos de URL y de nombre.
    • Rutas parciales con only() y except().
    • Concepto de middleware.
    • Aplicación a una ruta o grupo.
    • Protección de zonas privadas.
    • Middleware personalizado.

    Práctica

    Agrupar rutas:

    Route::prefix('admin')
    ->name('admin.')
    ->middleware(['auth'])
    ->group(function () {
        Route::resource('productos', ProductoController::class);
    });

    Crear un middleware:

    php artisan make:middleware ComprobarProductoActivo

    Registrar una ruta pública y otra protegida para comprobar la diferencia.

    Las rutas pueden organizarse mediante prefijos, nombres y middleware compartido.

    Evidencia

    Grupo de administración con prefijo de URL, prefijo de nombre y middleware.

    Sesión 10. Validación y autenticación con Breeze

    Archivos

    1. Validación formularios
    2. Autenticación Breeze

    Distribución temporal

    Tiempo Contenido
    0–30 min Validación básica en el controlador
    30–50 min Form Requests
    50–70 min Errores,old() y mensajes personalizados
    70–90 min Instalación de Breeze
    90–105 min Registro, inicio y cierre de sesión
    105–115 min Protección del CRUD
    115–120 min Comprobación final

    Contenidos principales

    • $request->validate().
    • Reglas habituales.
    • Form Requests.
    • Método validated().
    • Mensajes personalizados.
    • Visualización de errores con @error.
    • Recuperación de datos con old().
    • Instalación de Laravel Breeze.
    • Registro de usuarios.
    • Inicio y cierre de sesión.
    • Middleware auth.
    • Directivas @auth y @guest.
    • Protección de operaciones de creación, edición y eliminación.

    Práctica de validación

    php artisan make:request StoreProductoRequest
php artisan make:request UpdateProductoRequest

    Ejemplo de reglas:

    public function rules(): array
{
    return [
        'categoria_id' => ['required', 'exists:categorias,id'],
        'nombre' => ['required', 'string', 'min:3', 'max:255'],
        'descripcion' => ['nullable', 'string', 'max:1000'],
        'precio' => ['required', 'numeric', 'min:0'],
        'stock' => ['required', 'integer', 'min:0'],
        'activo' => ['nullable', 'boolean'],
    ];
}

    Práctica de autenticación

    Instalar Breeze siguiendo la variante Blade correspondiente al proyecto y ejecutar sus migraciones y dependencias frontend. Después, proteger las operaciones privadas:

    Route::resource('productos', ProductoController::class)
    ->middleware('auth')
    ->except(['index', 'show']);

    En el menú:

    @guest
    <a href="{{ route('login') }}">Iniciar sesión</a>
    <a href="{{ route('register') }}">Registrarse</a>
@endguest

@auth
    <a href="{{ route('productos.create') }}">Nuevo producto</a>
@endauth

    Evidencia final

    CRUD completo que permita:

    • Consultar productos sin autenticación.
    • Registrarse e iniciar sesión.
    • Crear, editar y eliminar únicamente tras autenticarse.
    • Validar todos los formularios.
    • Mostrar mensajes de error y conservar los valores introducidos.
    • Cerrar sesión correctamente.
